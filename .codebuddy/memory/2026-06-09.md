## llm-proxy v3 修复 StatsPage 各模型花费明细今日无数据

**根因**：两个问题叠加：
1. `GetModelStats` 只查询 `request_logs`，未用混合架构（hourly_stats + request_logs）
2. 更关键：SQLite 中 `hourly_stats.hour` 存储为 ISO 8601 格式（`2026-06-09T00:00:00+08:00`），`substr(hour, 1, 10)` 得到 `2026-06-09T`（带 T），前端比较 `2026-06-09`（无 T），导致匹配失败

**修复**：
1. `HourlyStatRepository.GetModelDailyStats` — 新增方法，SQLite 用 `date(hour)` 提取日期（返回 `YYYY-MM-DD`），MySQL 用 `DATE(hour)`
2. `RequestLogRepository.GetCurrentHourModelStats` — 新增方法，从明细表查当前小时模型级实时统计
3. `StatsService.GetModelStats` — 改为混合查询：汇总表历史 + 明细表当前小时，按 (date, provider_id, model) 合并排序

**教训**：SQLite 中 `time.Time` 存储为 ISO 8601（如 `2026-06-09T00:00:00+08:00`），`substr(col, 1, 10)` 会包含 `T`，`date()` 函数对带时区偏移的格式也不可靠，必须用 `strftime('%Y-%m-%d', col)` 提取纯日期

## RealtimePage Wails Events 三个 bug 修复 (2026-06-09)

修复了实时监控推送模式下的三个 bug，根本原因是前端事件回调数据访问层级错误：

### 根因
Wails `Events.On` 回调接收的是 `WailsEvent { name, data }` 对象，而非原始数据。Go 端 `app.Event.Emit("active-request:add", change)` 发送 `ActiveTrackerChange`，前端收到的 `event.data` 就是 `ActiveTrackerChange`（含 `type`/`request_id`/`data` 字段），`event.data.data` 才是 `ActiveRequest`。

### Bug 1: Provider 一直显示"匹配中..."
- `update` 事件正确发出，但前端 `change.data` 是 `ActiveTrackerChange`（无 `provider` 字段），应该用 `change.data.data` 获取 `ActiveRequest`

### Bug 2: 时间显示"NaNs"
- `start_time` 在 `ActiveRequest` 上，但代码从 `ActiveTrackerChange` 取 `start_time`（undefined）→ `new Date(undefined)` → NaN

### Bug 3: 请求完成不删除
- `remove` 事件中 `change.request_id` 是 `WailsEvent` 的属性（undefined），应该用 `change.data.request_id`

### 修复
- `RealtimePage.tsx`: 事件处理器重写为正确的数据访问模式：
  - `event.data` → `ActiveTrackerChange`
  - `change.data` → `ActiveRequest`
  - `change.request_id` → 请求 ID
- `active_tracker.go`: `debounceTimers` 添加 `debounceMu sync.Mutex` 保护并发访问；`Remove` 清理 debounce 计时器防止内存泄漏

### 验证
- `tsc --noEmit` 通过
- `go vet ./...` 通过
- `wails3 build` 成功（bin/llm-proxy.exe）
