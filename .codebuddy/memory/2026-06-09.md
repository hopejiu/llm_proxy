## 架构审查（UX/UI 视角）2026-06-09

用 improve-codebase-architecture skill 分析了前端和后端代码。报告输出到 `%TEMP%\architecture-review-llm-proxy-uxui-20260609.html`。

### 发现的后端候选（从 UX/UI 视角）
- **B1 (Strong) - WebHandler God Object**: 12 个不相关端点堆在一个 9KB 文件中，建议按前端页面拆为 5 个 handler
- **B2 (Strong) - VO.go DTO 堆积场**: 8 个 VO 类型 + 7 个转换函数全在 package main，建议按服务拆分子包
- **B3 (Worth exploring) - StatsService 职责混杂**: 混合统计聚合和日志查询，建议提取独立 LogService

### 发现的前端候选
- **F1 (Strong) - Modal 组件重复 3 次**: ProvidersPage/RealtimePage/StatsPage 都实现了相同 modal 结构
- **F2 (Worth exploring) - LoadingSpinner 重复 5 处**: 5 个页面有几乎相同的 spinner HTML
- **F3 (Worth exploring) - 错误处理不一致**: 5 种模式 (alert/内联banner/静默/console/logger)，用户体验割裂
- **F4 (Strong) - StatsPage God Page**: 290 行单组件管 6 个数据源，建议拆子组件
- **F5 (Speculative) - localStorage 手动序列化重复**
- **F6 (Speculative) - Wails 绑定直接调用缺乏抽象层**

### Top 推荐
1. **F1+F2**: 提取 Modal + LoadingSpinner（零风险，立即受益）
2. **B1**: 拆分 WebHandler（最高后端 ROI）

## Wails v3 构建体积分析 (2026-06-09)

用户询问为什么 `wails3 build` 后体积这么大（~30 MB）。分析结果：

### 构建产物
- `bin/llm-proxy.exe`: 30.15 MB (31,622,144 bytes)
- `frontend/dist`: 1.1 MB (嵌入二进制)
- Go 模块: 227 个 (111 个有本地目录)

### 主要体积来源
1. **Go 运行时 + 标准库**: ~5-10 MB
2. **Wails v3 框架**: ~5-10 MB (WebView2 绑定、运行时、go-git 依赖)
3. **Gin 框架 + quic-go**: ~3-5 MB (gin 间接依赖 quic-go/http3)
4. **GORM + SQLite/MySQL 驱动**: ~2-3 MB (glebarez/sqlite 纯 Go 实现)
5. **嵌入前端资源**: 1.1 MB (React + ECharts + Tailwind)
6. **其他间接依赖**: ~5 MB (go-git、quic-go、protobuf 等)

### 依赖链
- `quic-go`: gin → quic-go/http3 → quic-go (HTTP/3 支持)
- `go-git`: wails/v3 → go-git (Git 集成)

### 优化建议
1. **UPX 压缩**: 可减小 50-60% (30MB → 12-15MB)
2. **去除未使用依赖**: 检查是否可移除 quic-go (gin 的 HTTP/3 可选)
3. **前端优化**: ECharts 按需引入，减少打包体积
4. **考虑 server build**: 无 GUI 模式可减少 WebView2 相关代码

## 依赖优化分析 (2026-06-09)

用户要求分析 ECharts 按需引入、移除 quic-go、评估 go-git 必要性。

### ECharts 按需引入
- **现状**: 已使用按需引入 (StatsPage.tsx)
- **导入**: echarts/core, BarChart, LineChart, GridComponent, TooltipComponent, LegendComponent, CanvasRenderer
- **打包大小**: 1.1 MB (前端整体)
- **结论**: 已优化，无需进一步操作

### quic-go 移除
- **依赖路径**: gin → quic-go/http3 → quic-go (HTTP/3 支持)
- **状态**: 间接依赖，非直接使用
- **移除难度**: 高，需修改 gin 配置或使用无 HTTP/3 的 gin 版本
- **建议**: 保持现状，gin 默认不启用 HTTP/3，仅作为可选依赖

### go-git 必要性评估
- **依赖路径**: wails/v3 → go-git (Git 集成)
- **使用情况**: Go 源文件中无直接引用 (0 次)
- **必要性**: Wails 框架内部使用，用于 Git 集成功能
- **移除难度**: 极高，需修改 Wails 框架或使用无 Git 的 Wails 版本
- **建议**: 保持现状，属于框架核心依赖

### 优化建议总结
1. **ECharts**: 已优化，无需操作
2. **quic-go**: 保持现状，间接依赖，移除风险高
3. **go-git**: 保持现状，框架核心依赖
4. **UPX 压缩**: 最有效优化手段，可减小 50-60%
