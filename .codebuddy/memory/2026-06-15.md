# 2026-06-15

## Auto 默认模型功能（model=auto）

当客户端请求 `model=auto` 时，自动使用配置的默认模型。全局配置，存储在 `.env`（`AUTO_MODEL=providerID:modelName`）。

### 改动清单

**后端**
- `internal/config/config.go`: `Config` 新增 `AutoModel` 字段 + `GetAutoModel()` getter + `HotUpdate()` 读取
- `app_service.go`: 新增 `GetAutoModel() string` / `SetAutoModel(val string) error` Wails 绑定
- `internal/service/proxy_service.go`: 新增 `ResolveAutoModel(body, autoModelCfg)` — 解析请求体，若 `model=="auto"` 则替换为配置值
- `internal/handler/base_handler.go`: `HandleProxyRequest` 中 body 读取后调用 `ResolveAutoModel`

**前端**
- `frontend/src/services/index.ts`: `AppAPI` 新增 `getAutoModel()` / `setAutoModel(val)`
- `frontend/src/pages/ProvidersPage.tsx`: 搜索框下方新增"Auto 默认模型"section-card，复合 `<select>` 下拉（Provider→模型），选择后自动保存

### 请求处理流程
```
请求 {"model":"auto"}
  → HandleProxyRequest 读取 body
  → proxyService.ResolveAutoModel(body, cfg.GetAutoModel())
    → 若 model=="auto" 且 AUTO_MODEL 已配置，替换 body 中的 model
    → 修改后 body: {"model":"gpt-4"}
  → 后续全链路不变（GetProviderByModel, FindModelEntry 正常工作）
```

## 修复 MySQL 启动失败：旧索引 idx_hour_provider 未删除

**错误**: `Error 1062 (23000): Duplicate entry '...' for key 'idx_hour_provider'`  
**根因**: `dropOldHourlyIndexes` 依赖 `information_schema.STATISTICS` 查询检测旧索引，某些 MySQL 环境下查询返回 0 导致跳过删除。旧 2 列唯一索引 `idx_hour_provider(hour, provider_id)` 遗留，`AutoMigrate` 操作表时触发冲突。  
**修复**: `app_bootstrap.go` 中移除 information_schema 检查，直接执行 `DROP INDEX`，索引不存在时记录 Debug 日志（错误码 1091）。
